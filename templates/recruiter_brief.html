The Making of SentinelX: Engineering Brief

A Recruiter-Focused Overview of Architecture, Engineering Decisions, and Measurable Impact

Author: Mukesh Jena (MCA | SOC Analyst & Detection Engineer) · Return to Live SIEM

Executive Summary (In 60 Seconds)

SentinelX is an end-to-end, production-grade Security Operations Center (SOC) platform designed to eliminate the latency between adversary activity and automated containment. Rather than demonstrating isolated tools, this project demonstrates an integrated, zero-trust telemetry pipeline combining Wazuh (EDR/SIEM), Zeek (Network Security Monitoring), MISP (Threat Intelligence), Sysmon (Process Telemetry), and Python Automation with RFC 6238 TOTP 2FA and interactive SOAR containment.

🏗️ The 4-Phase Engineering Process

Phase 1: Lab Architecture & Threat Modeling

Isolated Multi-OS SOC Network

  • Configured VirtualBox host-only LAN separating corporate network from attack telemetry.
  • Windows 11 Endpoint (10.0.2.15): Monitored via Microsoft Sysmon (modular SwiftOnSecurity configuration) and Wazuh Agent 001.
  • Ubuntu SOC Server (10.0.2.4): Hosted Wazuh Manager, Wazuh Indexer, Zeek network tapping, and MISP threat sharing instance.
  • Kali Linux Node: Used for controlled red team command emulation and beaconing generation.
Phase 2: Telemetry Pipeline & ECS Normalization

Heterogeneous Log Ingestion into Elastic Common Schema

  • Engineered Python ingestion pipeline capable of parsing Zeek TSV logs (http.log, conn.log), Wazuh Manager JSON alerts, and Sysmon process events.
  • Normalized all fields to ECS standards: event_id, timestamp, host, src_ip, dst_ip, process_name, command_line, hashes.
  • Implemented automated regex IOC extractor isolating IPv4, domains, and SHA256 hashes in <15ms.
Phase 3: Threat Intelligence & Controlled Positive Validation

Positive IOC Validation Flow (192.0.2.123)

  • Executed positive control validation: Generated HTTP request from Windows 11 endpoint with Host 192.0.2.123.
  • Zeek captured transaction, SentinelX Python extracted indicator, and queried MISP via PyMISP.
  • MISP confirmed positive match: Event ID 1, Category: Network activity, Type: ip-dst. Saved structured JSON evidence to disk.
  • Mapped detection rules directly to MITRE ATT&CK tactics (T1059.001, T1071.001, T1003.001, T1573, T1490).
Phase 4: Zero-Trust 2FA Security & SOAR Platform

Production Web UI, 2FA, and Docker Orchestration

  • Enforced Zero-Trust authentication: PBKDF2-HMAC-SHA256 password hashing (200,000 iterations) and RFC 6238 TOTP 2FA with live QR onboarding.
  • Built automated SOAR playbooks: Instant IP firewall drop rules, Wazuh active-response host isolation, and MISP threat indicator tagging.
  • Packaged as multi-stage, non-root Docker container with Docker Compose and 1-click cloud deployment specs.
